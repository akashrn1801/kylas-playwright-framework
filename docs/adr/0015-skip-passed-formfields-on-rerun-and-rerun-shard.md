# ADR 0015 — A re-run skips formFields jobs that already passed; rerun shard for failed and flaky tests

> **Purpose:** Records how a re-run of one failed core shard avoids repeating the formFields jobs (sandbox first), and the rerun-shard design that later steps build on.
> **Read when:** Editing `.github/scripts/formfields-attempt-gate.sh`, the gate steps or `overwrite: true` uploads in `sandbox.yml`, or starting the rerun-shard work.
> **Size budget:** 13k chars (hard cap 60k; raised from 8k on 2026-11-24 and to 13k on 2026-11-25 for the amendments below)
> **Last verified:** 2026-11-25 @ 3ac81e5

## Status
Proposed — 2026-11-03. **Amended 2026-11-24 (build #235 email review): a test that passes on the rerun counts as Passed after the rerun (the Combine, One email and Consequences bullets say how). Second amendment, same day: the "After rerun" column becomes "Final result" and counts every test that ULTIMATELY passed as Passed, whether clean, after an in-job retry (flaky) or on the rerun (build #235: Passed 940, Failed 2, Flaky 0, Skipped 1); see "Second amendment" below.** Everything else below is unchanged. **Implemented in `sandbox.yml` only (attempt gate, rerun shard, manual rerun workflow, combined report/email/history); nothing has run on GitHub.** qa/stage/main are unchanged. The job order stays core shards → formFields → reset → merge, with the rerun shard added right after the core shards: `detect → run-tests → rerun-failed → run-formfields-tests → reset-field-config → merge-and-report`. ([ADR 0007](0007-sequence-formfields-after-core.md) still describes the qa/stage/main order.)

## Context
- formFields jobs `needs` the core shards, so GitHub's "Re-run failed jobs" / "Re-run job" on one failed core shard also re-runs the dependent formFields matrix jobs (about 80-110 min each), the reset and the merge. A job that passed in an earlier attempt of the same run has nothing to prove again; its artifacts stay in the run.
- A transient failure should read as "passed on rerun", not as a red test. (Before the 2026-11-24 amendment a rerun pass counted as Flaky, never Passed; build #235's email then said "Passed 932" next to "2 recovered", and the headline disagreed with the rerun table's own meaning. Now Passed counts the rerun passes; "Passed first time" and the history keep the first attempt, and a test that failed every first attempt still keeps the verdict amber.)

## Decision
- **Attempt gate** (`.github/scripts/formfields-attempt-gate.sh ff|reset`, token `PIPELINE_TOKEN` else `github.token`, `actions: read`): writes `skip=true|false`, always exits 0, never skips on doubt. A formFields job skips every step after checkout when `run_attempt > 1`, the same job name concluded success earlier with its test step succeeded and its `blob-report-sandbox-formfields-<entity>` artifact not expired ("formFields <entity> already passed in attempt N — skipped"). `reset-field-config` skips when no formFields job ran tests in this attempt. "Re-run all jobs" (detect re-ran) skips nothing. All `sandbox.yml` uploads use `overwrite: true`.
- **Rerun shard** (`rerun-failed`, job name `playwright-rerun (failed+flaky)`, `needs: [detect, run-tests]`, runs only when repo variable `RERUN_SHARD == 'on'`; `RERUN_MAX_TESTS` default 60, `RERUN_RETRIES` default 0, `RERUN_INCLUDE_FLAKY` default false since 2026-11-25, see the third amendment). It merges the core blobs (`blob-report-sandbox-[0-9]*`) with `merge-json.config.ts`, `scripts/rerun-select.ts` picks, from the blobs (never `.last-run.json`): if the first run has ANY failed, timed-out, cut-off or "did not run" test (a failed formFields test counts) only those are rerun and the flaky ones are not; if it has none, the flaky tests are rerun, targets `file:line` or the whole file for serial files, never formFields tests, nothing above the cap (a mass failure is an outage). It reruns once with `--workers=2 --retries=$RERUN_RETRIES` and always exits 0. Artifacts `rerun-manifest-sandbox` (always, with run id + attempt), `rerun-blob-sandbox`, `rerun-misc-errors-sandbox`, `rerun-test-results-sandbox`: none matches `blob-report-sandbox-*` or `misc-errors-sandbox-*`, so shard completeness (core + formFields) is unaffected. formFields `needs` it with `!cancelled()`; a re-run of a core shard re-runs it (it re-selects from the latest blobs).
- **Combine** (`scripts/combine-rerun.ts`, in `merge-and-report`): merging both blobs duplicates test rows, so rerun results are appended to the first-run test and its status recomputed. **A rerun pass is a pass (amended 2026-11-24):** Failed first + rerun pass = Passed; Flaky first + rerun pass = Passed; Failed + rerun fail = Failed; Flaky first + rerun fail stays Flaky (extra executions never turn it into a failure); a test that passed in an earlier rerun stays Passed; a test that did not run (serial dependent, cut-off shard) never failed: Did not run + rerun pass = Passed ("ran only on rerun"), + rerun fail = Failed. `ReportParser` keeps what the first run made of each test (`TestResult.firstRunStatus`, `passedOnRerun`, `recoveredOnRerun` = failed every first attempt, `flakyPassedOnRerun`) and `ParsedReport.firstRun` counts. Summaries written before the amendment (`recovered`, or Flaky after a rerun pass) read as Passed. **Run colour, decision 2026-11-03, amended:** failed after the rerun = red; a test that failed every first attempt and passed only on the rerun (`recoveredOnRerun`), a still-flaky test, a did-not-run or ran-only-on-rerun test = amber ("Unstable — N flaky, M passed only on rerun"); a flaky-first test that passed on the rerun is resolved and, alone, the run is green; the health score's Flakiness factor also counts `recoveredOnRerun`. Table columns add up (passed + failed + flaky + skipped + did not run = total); nothing to rerun and nothing excluded = no section; tests not rerun are listed with the selector's own reason. A manifest of another attempt, or none, changes nothing. Writes `reports/<env>/rerun-summary.json` (`recovered` = tests that passed on the rerun after being Failed or Flaky); `results.first-run.json` keeps the original.
- **One email**: summary table "First run | After rerun" (Passed includes "N passed on rerun") and per test first run → rerun → final ("Passed on rerun"); a "Passed on rerun" section keeps their first-run failure; headline, verdict, health, subject and dedup inputs use the after-rerun counts, while "Passed first time" (and its delta and series) is the first-run figure so a run with any test that did not pass first time never reads 100% (e700d3a). **History keeps the first-run counts** (`passed`/`failed`/`flaky`/`skipped`, per-module counts) and adds `afterRerun`, `rerun`, `firstRunFailed`, `firstRunFlaky`, `recoveredOnRerunTitles`; `flakyTestTitles` still includes every test that passed only on the rerun (recurring-flaky keeps counting it), `failedTestTitles` only those still failing. Records before the amendment hold after-rerun counts (a recovered test counted flaky) and have no `afterRerun`.
- **Manual rerun** (`.github/workflows/rerun-failed.yml`, `workflow_dispatch`: `run_id`, `env` qa|staging, `include_flaky`): group `kylas-<env>`, no formFields, reads the run's 14-day `playwright-report-*` and `run-meta-*` artifacts (sandbox runs only for now), checks out a ref whose `tests/ src/ config/` equal the run's commit, then selects, reruns, combines, syncs history under the ORIGINAL build number (replaces that record) and sends the one email.
- Run conclusion stays red if any shard failed (option A); the email shows what recovered.

## Second amendment 2026-11-24: Final result
- **Rule:** the rerun table's second column is **Final result**: Passed = every test that ultimately passed (clean 932 + 6 after an in-job retry + 2 after the rerun = 940), Failed = 2, Flaky = 0 ("(the 6 ended Passed)"), Skipped 1. A flaky test ends as Passed even if the rerun fails it (it did pass on its in-job retry; extra executions never turn it into a failure). `countStatuses(report, finalOutcome)` and `ParsedReport.finalPassed` (= passed + flaky) carry it; `afterRerun` in history is the same view.
- **Instability stays visible, as a signal inside Passed, never as a second outcome:** the First run column (932 / 4 / 6), "Passed first time" (98.8%, first run), the Flaky tile (6) with "inside Passed", the Flaky Tests and Passed on rerun sections with each test's error, the subject `2 failed, 940 passed (6 flaky, 2 on rerun) of 943`, the health Flakiness factor (flaky + failed-first-passed-on-rerun), history first-run counts and flaky titles. The breakdown under Passed is disjoint: clean + after a retry (`firstRun.flaky`, even if the rerun confirmed it) + after the rerun (`recoveredOnRerun`) + ran only on the rerun.
- **Verdict (D2 unchanged):** red if anything failed in the end; amber if a test is still flaky, failed every first attempt and passed only on the rerun, did not run or ran only on the rerun; green otherwise.
- **Found by the scenario matrix (`npm run check:scenarios`) and fixed:** the first version counted a flaky test that the rerun confirmed twice (table "after a retry", summary "after the rerun"); and "Not rerun: no test failed or was flaky" was printed for a run whose only failures were in never-rerun suites. Open findings (health "Excellent" next to FAILED, 0 tests reading "Passed", blocked/empty runs showing a pass rate, branch-aware advice) are listed in the matrix's KNOWN list with proposed fixes.

## Consequences
- Re-running a failed core shard costs that shard, the rerun job and seconds for passed formFields jobs. The rerun job re-selects every failed/flaky core test again, including those of shards that were not re-run.
- Limits: the merged HTML report stays the first run (`results.json` is combined); the rerun job's misc errors are merged since 2026-11-24 (`misc-errors-sandbox-rerun`, label `sandbox-rerun`); a whole-file rerun of a serial file ignores the shard's `--grep`; formFields tests are never rerun (v1); JobStats shows the latest attempt only.
- **UNVERIFIED (no GitHub doc found; prove on sandbox):** (1) a later attempt's `merge-and-report` downloads artifacts uploaded in an earlier attempt of the same run; (2) how `attempts/N/jobs` lists a job that was not re-run; (3) `overwrite: true` replaces the earlier artifact on re-upload; (4) `PIPELINE_TOKEN` can read the attempts-jobs and artifacts endpoints; (5) `.path` of a run in the runs API is the plain workflow path; (6) `blob-report-sandbox-[0-9]*` matches as a glob in `download-artifact`; (7) `spec.line` is the same in the first run and the rerun. If (1) fails the email says INCOMPLETE (honest, not green).
- Tested offline only: `npm run check:rerun` (unit + 21 end-to-end scenarios; the gate's own check is `check:formfields-gate`), `check:build235` (build #235 replayed from a fixture), `check:failure-labels`, actionlint.

## How to revert
Switch off without a code change: set the variable `RERUN_SHARD` to anything but `on` (the attempt gate stays). Full revert: delete the `rerun-failed` job, its `needs` entries, the download/combine/`run-meta-sandbox` steps and the two `gate` steps with their `if` conditions, `actions: read` and `overwrite: true` lines in `sandbox.yml`; delete `rerun-failed.yml`, `formfields-attempt-gate.sh`, `merge-json.config.ts`, `scripts/rerun-select.ts`, `scripts/combine-rerun.ts`, `scripts/check-rerun.ts`, `src/notifications/RerunResults.ts` and `RerunSummary.ts` and their uses in `EmailTemplate.ts`, `NotificationService.ts`, `syncHistory.ts`, `RunHistory.ts`.

## Third amendment (2026-11-25): colour by results only
The verdict colour no longer depends on whether a rerun ran. Green when everything passed in the end, flaky tests (passed on an in-job retry) are at most `FLAKY_BUDGET` (3) and no test failed every attempt; amber when flaky is above the budget, a test passed only on the rerun after failing every first attempt (D2), or tests did not run or ran only on the rerun; red for any failure. `RERUN_INCLUDE_FLAKY` defaults to off: a flaky test already passed, so rerunning it cannot change a number or the colour (failed tests are still rerun). The subject always names the flaky count.
