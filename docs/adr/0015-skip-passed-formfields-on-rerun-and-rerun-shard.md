# ADR 0015 — A re-run skips formFields jobs that already passed; rerun shard for failed and flaky tests

> **Purpose:** Records how a re-run of one failed core shard avoids repeating the formFields jobs (sandbox first), and the rerun-shard design that later steps build on.
> **Read when:** Editing `.github/scripts/formfields-attempt-gate.sh`, the gate steps or `overwrite: true` uploads in `sandbox.yml`, or starting the rerun-shard work.
> **Size budget:** 8k chars (hard cap 60k)
> **Last verified:** 2026-11-03 @ 1c1000e

## Status
Proposed — 2026-11-03. **Implemented in `sandbox.yml` only (attempt gate, rerun shard, manual rerun workflow, combined report/email/history); nothing has run on GitHub.** qa/stage/main are unchanged. The job order stays core shards → formFields → reset → merge, with the rerun shard added right after the core shards: `detect → run-tests → rerun-failed → run-formfields-tests → reset-field-config → merge-and-report`. ([ADR 0007](0007-sequence-formfields-after-core.md) still describes the qa/stage/main order.)

## Context
- formFields jobs `needs` the core shards, so GitHub's "Re-run failed jobs" / "Re-run job" on one failed core shard also re-runs the dependent formFields matrix jobs (about 80-110 min each), the reset and the merge. A job that passed in an earlier attempt of the same run has nothing to prove again; its artifacts stay in the run.
- A transient failure should read as "recovered on rerun", not as a red test, but a rerun pass must never look like a clean pass.

## Decision
- **Attempt gate** (`.github/scripts/formfields-attempt-gate.sh ff|reset`, token `PIPELINE_TOKEN` else `github.token`, `actions: read`): writes `skip=true|false`, always exits 0, never skips on doubt. A formFields job skips every step after checkout when `run_attempt > 1`, the same job name concluded success earlier with its test step succeeded and its `blob-report-sandbox-formfields-<entity>` artifact not expired ("formFields <entity> already passed in attempt N — skipped"). `reset-field-config` skips when no formFields job ran tests in this attempt. "Re-run all jobs" (detect re-ran) skips nothing. All `sandbox.yml` uploads use `overwrite: true`.
- **Rerun shard** (`rerun-failed`, job name `playwright-rerun (failed+flaky)`, `needs: [detect, run-tests]`, runs only when repo variable `RERUN_SHARD == 'on'`; `RERUN_MAX_TESTS` default 60, `RERUN_RETRIES` default 0, `RERUN_INCLUDE_FLAKY` default true). It merges the core blobs (`blob-report-sandbox-[0-9]*`) with `merge-json.config.ts`, `scripts/rerun-select.ts` picks, from the blobs (never `.last-run.json`): if the first run has ANY failed, timed-out, cut-off or "did not run" test (a failed formFields test counts) only those are rerun and the flaky ones are not; if it has none, the flaky tests are rerun, targets `file:line` or the whole file for serial files, never formFields tests, nothing above the cap (a mass failure is an outage). It reruns once with `--workers=2 --retries=$RERUN_RETRIES` and always exits 0. Artifacts `rerun-manifest-sandbox` (always, with run id + attempt), `rerun-blob-sandbox`, `rerun-misc-errors-sandbox`, `rerun-test-results-sandbox`: none matches `blob-report-sandbox-*` or `misc-errors-sandbox-*`, so shard completeness (core + formFields) is unaffected. formFields `needs` it with `!cancelled()`; a re-run of a core shard re-runs it (it re-selects from the latest blobs).
- **Combine** (`scripts/combine-rerun.ts`, in `merge-and-report`): merging both blobs duplicates test rows, so rerun results are appended to the first-run test and its status recomputed. Failed first + rerun pass = Flaky "recovered on rerun"; failed + rerun fail = Failed; flaky first stays Flaky whatever the rerun does (so does a test recovered in an earlier rerun); a test that did not run (serial dependent, cut-off shard) never failed: Did not run + rerun pass = Passed ("did not run → passed on rerun", counted separately as "ran only on rerun"), + rerun fail = Failed. **Run colour (`ReportParser`, `AutomationHealth`), decision 2026-11-03:** first run with only flaky tests: all pass on the rerun = GREEN (listed as "Flaky - passed on rerun", still flaky in counts, `flakyTestTitles`, trends), any fails on the rerun = amber. First run with failed/timed-out/did-not-run tests: recovered = amber, still failing = red, and its flaky tests (not rerun) keep it at least amber. Otherwise green only when every test passed on its first try (`TestResult.flakyPassedOnRerun` marks the resolved ones). A test that did not run (skipped without a skip annotation) or ran only on the rerun makes a failure-free run amber ("N did not run" / "N ran only on rerun"); deliberate skips never change the colour. Table columns add up (passed + failed + flaky + skipped + did not run = total); nothing to rerun and nothing excluded = no section. A manifest of another attempt, or none, changes nothing. Writes `reports/<env>/rerun-summary.json`; `results.first-run.json` keeps the original.
- **One email**: summary table "First run | After rerun" (Passed / Failed / Flaky, "recovered on rerun" counted as flaky) and per test first run → rerun → final, also on each failed card and flaky row; verdict, health, subject and dedup inputs come from the combined report. History keeps `failed`/`flaky` as final counts, recovered titles in `flakyTestTitles`, plus optional `rerun`, `firstRunFailed`, `firstRunFlaky`, `recoveredOnRerunTitles`.
- **Manual rerun** (`.github/workflows/rerun-failed.yml`, `workflow_dispatch`: `run_id`, `env` qa|staging, `include_flaky`): group `kylas-<env>`, no formFields, reads the run's 14-day `playwright-report-*` and `run-meta-*` artifacts (sandbox runs only for now), checks out a ref whose `tests/ src/ config/` equal the run's commit, then selects, reruns, combines, syncs history under the ORIGINAL build number (replaces that record) and sends the one email.
- Run conclusion stays red if any shard failed (option A); the email shows what recovered.

## Consequences
- Re-running a failed core shard costs that shard, the rerun job and seconds for passed formFields jobs. The rerun job re-selects every failed/flaky core test again, including those of shards that were not re-run.
- Limits: the merged HTML report stays the first run (`results.json` is combined); rerun misc errors are not aggregated; a whole-file rerun of a serial file ignores the shard's `--grep`; formFields tests are never rerun (v1); JobStats shows the latest attempt only.
- **UNVERIFIED (no GitHub doc found; prove on sandbox):** (1) a later attempt's `merge-and-report` downloads artifacts uploaded in an earlier attempt of the same run; (2) how `attempts/N/jobs` lists a job that was not re-run; (3) `overwrite: true` replaces the earlier artifact on re-upload; (4) `PIPELINE_TOKEN` can read the attempts-jobs and artifacts endpoints; (5) `.path` of a run in the runs API is the plain workflow path; (6) `blob-report-sandbox-[0-9]*` matches as a glob in `download-artifact`; (7) `spec.line` is the same in the first run and the rerun. If (1) fails the email says INCOMPLETE (honest, not green).
- Tested offline only: `npm run check:rerun` (unit + 21 end-to-end scenarios, gate on a stub `gh`), `check:failure-labels`, actionlint.

## How to revert
Switch off without a code change: set the variable `RERUN_SHARD` to anything but `on` (the attempt gate stays). Full revert: delete the `rerun-failed` job, its `needs` entries, the download/combine/`run-meta-sandbox` steps and the two `gate` steps with their `if` conditions, `actions: read` and `overwrite: true` lines in `sandbox.yml`; delete `rerun-failed.yml`, `formfields-attempt-gate.sh`, `merge-json.config.ts`, `scripts/rerun-select.ts`, `scripts/combine-rerun.ts`, `scripts/check-rerun.ts`, `src/notifications/RerunResults.ts` and `RerunSummary.ts` and their uses in `EmailTemplate.ts`, `NotificationService.ts`, `syncHistory.ts`, `RunHistory.ts`.
